# دانلود Digital Concert Hall با `ytdlp-tool dch`

> وضعیت: پیاده‌سازی و با تست‌های واحد (بدون شبکه) و بررسی extractor واقعی yt-dlp راستی‌آزمایی شده است.
> **دانلود واقعی روی حساب شما هنوز آزمایش نشده**؛ نتیجه‌ی آن (کیفیت، DRM، عمر توکن) فقط با اجرای
> «مرحله‌ی آزمایش» پایین مشخص می‌شود. پیشینه و دلیل این طراحی: [مرور پلن](digital-concert-hall-plan-review.md).

## چرا توکن؟

ورود با نام کاربری/رمز در این سایت دیگر ممکن نیست. extractor رسمی yt-dlp فقط یک **access token**
از مرورگر واردشده‌ی خودتان می‌پذیرد (مقدار `access_token_production` در Local Storage). این دستور همان
مسیر رسمی را با رعایت چند قاعده‌ی ایمنی اجرا می‌کند.

## استفاده

۱. در Brave وارد سایت شوید. DevTools ← Application ← Local Storage ← `https://www.digitalconcerthall.com`
← مقدار `access_token_production` را کپی کنید (فقط داخل ترمینال Ops پیست می‌شود، نه در گفتگو).

۲. روی Ops:

```powershell
# فهرست بخش‌ها و بهترین کیفیت موجود (چیزی دانلود نمی‌شود)
ytdlp-tool dch "https://www.digitalconcerthall.com/en/concert/56205" --list

# دانلود همه‌ی بخش‌ها
ytdlp-tool dch "https://www.digitalconcerthall.com/en/concert/56205"

# فقط بخش دوم، با سقف کیفیت
ytdlp-tool dch "https://www.digitalconcerthall.com/en/concert/56205" --item 2 --format-selector "bv*[height<=1080]+ba/b"
```

دستور توکن را با ورودی مخفی می‌پرسد (چیزی روی صفحه نشان داده نمی‌شود). برای اسکریپت:
`... --token-stdin` و توکن را از stdin بدهید (هرگز به‌صورت آرگومان یا متغیر محیطی نه).

خروجی پیش‌فرض: `output\digital-concert-hall\<عنوان> [<شناسه>]\NN - <عنوان بخش> [<id>].<ext>`.
فایل‌های موجود بازنویسی نمی‌شوند.

آدرس‌های پذیرفته‌شده: `https://www.digitalconcerthall.com/<زبان>/(concert|film|work)/<شماره>[-<بخش>]`.

## تضمین‌های امنیتی (و راستی‌آزمایی آن‌ها)

| قاعده | چگونه تأمین می‌شود |
| --- | --- |
| توکن در argv / متغیر محیطی / فایل نیست | فقط prompt مخفی یا stdin (تست‌شده) |
| توکن روی دیسک ثبت نمی‌شود | `cachedir=False`؛ با extractor واقعی آزموده شد: بدون آن `tokens.json` ساخته می‌شود، با آن هیچ فایلی نه |
| توکن در خروجی/خطا دیده نمی‌شود | همه‌ی پیام‌های خطا scrub می‌شوند (تست‌شده) |
| توکن منقضی بی‌جهت درخواست نمی‌فرستد | انقضای JWT پیش از هر تماس شبکه بررسی می‌شود (کمتر از ۳۰ ثانیه = رد) |
| فقط همین سایت | URL باید `https` و دامنه‌ی `digitalconcerthall.com` و مسیر معتبر باشد؛ بدون user:pass |
| refresh token استفاده نمی‌شود | طبق پلن؛ پس توکن عمر محدود دارد |

## محدودیت‌ها و عدم‌قطعیت‌ها

* **عمر توکن نامعلوم است.** اگر وسط یک کنسرت چندبخشی منقضی شود، بخش‌های بعدی با خطای «token rejected» متوقف
  می‌شوند؛ بخش‌های کامل‌شده می‌مانند و با `--item N` ادامه می‌دهید. دستور هنگام شروع «حدود N دقیقه اعتبار» را چاپ می‌کند.
* کیفیت: extractor خودش می‌گوید جریان‌های ۴K/FLAC دیگر در دسترس نیست؛ `--list` کیفیت واقعی حساب شما را نشان می‌دهد.
* محتوای DRM یا بدون دسترسی با پیام صریح گزارش می‌شود؛ دور زدن آن‌ها بخشی از این ابزار نیست.
* به `ffmpeg` در PATH نیاز دارد.
* شرایط استفاده‌ی سایت درباره‌ی دانلود را بررسی نکرده‌ام؛ مسئولیت استفاده با شماست و فقط برای محتوایی است که حساب شما مجاز به پخش آن است.

## مرحله‌ی آزمایش (یک‌بار، ۵ دقیقه)

۱. `--list` را با توکن تازه اجرا کنید ← باید بخش‌ها و کیفیت را ببینید.
۲. `--item 1` را روی کوتاه‌ترین بخش اجرا کنید ← فایل نهایی را با پخش‌کننده باز کنید.
۳. زمان بین «توکن تازه» تا «خطای انقضا» را یادداشت کنید (همان عمر توکن).

بر پایه‌ی نتیجه تصمیم بگیرید که آیا افزونه‌ی Brave و Native Messaging (پلن مراحل ۳–۴) ارزش ساخت دارد.
